Vérifications à faire maintenant :

1. Le CRS est chargé et Coraza écoute :
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c coraza | head -50

2. Le Caddyfile a bien été patché (bloc global servers + header_up) :
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c caddy-template-patch
   L'initContainer échoue bruyamment si les ancres du template amont ont bougé.

3. L'IP client réelle remonte de bout en bout — `client_ip` côté Caddy doit être
   l'IP publique du client, pas une IP de pod, et la sonde id:1099 doit rester
   muette :
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c coraza | grep -i client_ip
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c coraza | grep 1099

4. Les entrées d'audit "transaction" : elles manquent avec l'image amont, pour
   la même raison que la phase 4 (coraza-caddy v1.2.2). Vérifié en local : une
   image reconstruite avec coraza-caddy/v2 les produit sans autre changement.
   Inutile de chercher du côté de SecAuditEngine RelevantOnly.

5. Rechargement à chaud de la config Coraza — après un `helm upgrade` qui
   modifie la ConfigMap, le conteneur `coraza-reload` doit journaliser
   « rechargement appliqué » dans la minute qui suit (propagation kubelet) :
     kubectl -n {{ .Release.Namespace }} logs ds/{{ include "traefik-coraza.tfFullname" . }} -c coraza-reload
   Un « RECHARGEMENT REFUSÉ » signale une règle invalide : le WAF continue de
   tourner sur la configuration précédente, il n'y a pas de coupure, mais la
   ConfigMap et la config en vigueur ont divergé.

6. Middlewares IP existants — il n'y a PAS de défaut global, chaque middleware
   doit porter ipStrategy.depth: 1, sinon il compare le pair TCP (127.0.0.1)
   et renvoie 403 :
     kubectl get middlewares -A -o json | jq -r '.items[] | select(.spec.ipAllowList or .spec.rateLimit) | "\(.metadata.namespace)/\(.metadata.name)"'
