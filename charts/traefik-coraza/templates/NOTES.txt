Vérifications à faire maintenant :

1. Le binaire Caddy embarque bien coraza-caddy/v2, et le CRS est chargé :
     kubectl -n {{ .Release.Namespace }} logs ds/{{ include "traefik-coraza.tfFullname" . }} -c caddy-plugin-build
     kubectl -n {{ .Release.Namespace }} logs ds/{{ include "traefik-coraza.tfFullname" . }} -c coraza | head -50

2. Le Caddyfile a bien été patché (bloc global servers + header_up +
   read_timeout 0, ce dernier pour que les réponses en flux survivent au-delà
   des 60 s de silence du template amont) :
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c caddy-template-patch
   L'initContainer échoue bruyamment si les ancres du template amont ont bougé.

3. L'IP client réelle remonte de bout en bout — `client_ip` côté Caddy doit être
   l'IP publique du client, pas une IP de pod, et la sonde id:1099 doit rester
   muette :
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c coraza | grep -i client_ip
     kubectl -n {{ .Release.Namespace }} logs ds/traefik -c coraza | grep 1099

4. Les entrées d'audit "transaction" : elles manquent avec l'image amont, pour
   la même raison que la phase 4 (coraza-caddy v1.2.2). Vérifié en local : une
   image reconstruite avec coraza-caddy/v2 les produit sans autre changement.
   Inutile de chercher du côté de SecAuditEngine RelevantOnly.

5. Changement de configuration — après un `helm upgrade` qui modifie la
   ConfigMap, le conteneur `coraza` doit redémarrer UNE fois dans les deux
   minutes (propagation kubelet + période de sonde), et une seule :
     kubectl -n {{ .Release.Namespace }} get pod -l app.kubernetes.io/name={{ include "traefik-coraza.tfNameLabel" . }} \
       -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.containerStatuses[?(@.name=="coraza")].restartCount}{"\n"}{end}'
   Un compteur qui grimpe en continu signale une boucle : la sonde journalise sa
   décision dans les événements du pod.
   « config.d modifiée mais INVALIDE » signifie que le redémarrage a été REFUSÉ :
   le WAF tourne toujours sur la configuration précédente — pas de coupure, mais
   la ConfigMap et la configuration en vigueur ont divergé.

6. Réponses en flux — sur une application qui en produit (SSE, grpc-gateway,
   « watch » d'API), les octets doivent ressortir au fil de l'eau et non à la
   fin. Deux compteurs de la MÊME requête, le sandwich la faisant passer deux
   fois dans Traefik : `DownstreamContentSize` doit être non nul sur les DEUX
   passes (`internal` et `websecure`). Un 0 côté `websecure` avec une valeur
   côté `internal` = flux retenu par le WAF.

7. Middlewares IP existants — il n'y a PAS de défaut global, chaque middleware
   doit porter ipStrategy.depth: 1, sinon il compare le pair TCP (127.0.0.1)
   et renvoie 403 :
     kubectl get middlewares -A -o json | jq -r '.items[] | select(.spec.ipAllowList or .spec.rateLimit) | "\(.metadata.namespace)/\(.metadata.name)"'
