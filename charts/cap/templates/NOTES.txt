{{- if .Values.ingress.enabled }}
   1. Ouvrir https://{{ .Values.ingress.host }}/ et s'authentifier avec la
      valeur de ADMIN_KEY (Secret « {{ include "cap.adminSecretName" . }} », clé
      « {{ include "cap.adminSecretKey" . }} »).
{{- else }}
   1. Ouvrir l'IHM (port-forward sur le Service) et s'authentifier avec la
      valeur de ADMIN_KEY (Secret « {{ include "cap.adminSecretName" . }} »).
{{- end }}
   2. Créer une clé de site. Conserver siteKey ET secretKey.
   3. Les reporter chez le consommateur du captcha. Avec le chart
      traefik-coraza, bloc `bouncer:` de ses values :

        bouncer:
          captcha:
            enabled: true
            provider: custom
            keys:
              siteKey: "<cle publique>"
              secretKey: "<cle secrete>"
{{- if .Values.ingress.enabled }}
            jsURL: https://{{ .Values.ingress.host }}/assets/widget.js
            validateURL: http://{{ include "cap.fullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:{{ int .Values.cap.service.port }}/<siteKey>/siteverify
            widget:
              apiBaseURL: https://{{ .Values.ingress.host }}
              wasmURL: https://{{ .Values.ingress.host }}/assets/cap_wasm_bg.wasm
          attach:
            enabled: true
            middleware: captcha
            # 🛑 SANS CETTE LIGNE, UN VISITEUR EN REMÉDIATION NE PEUT PAS
            #    CHARGER LE WIDGET : son hôte passerait lui-même par le bouncer.
            bypassHosts: ["{{ .Values.ingress.host }}"]
{{- end }}

     curl -sI https://{{ .Values.ingress.host }}/assets/widget.js | head -1

3. Le partage des chemins tient — la racine doit demander à s'authentifier,
   et un chemin de clé de site rester public :
     curl -sI https://{{ .Values.ingress.host }}/ | head -1
     curl -sI https://{{ .Values.ingress.host }}/server/keys | head -1
   Un 200 sur la racine sans authentification = la priorité de routeur n'a pas
   pris, l'IHM est publique.
